# FREEZE 名单执行 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 FREEZE 整包封杀执行器 —— 引擎杀存量+巡检兜底，COSGuard hook 拦拉起，名单冲突双向拒绝。

**Architecture:** 名单 → lists.sh 冲突校验 → service.sh 写桥 FREEZE 行 → 双消费者（引擎 shell 执行杀；LSPosed hook 在 startProcess 路径拦截），遥测复用现有 6 字段管道与 guard_stats 聚合。

**Tech Stack:** Android shell (busybox ash)、awk、LSPosed/Xposed (Java)、JUnit5、vitest、bash 测试 harness（tests/run_tests.sh 的 t_assert/t_match）。

**Spec:** `docs/superpowers/specs/2026-09-30-freeze-design.md`（本计划每条要求以 spec 为准）

## Global Constraints

- FREEZE 语义：**在册即持续封杀，移出即解封**（spec D2），无时长参数；
- FREEZE **独立于 observe/guard**（spec D3）：hook 支不读 MODE；总闸 = `memory.json` `freeze.enabled`，由 service.sh 消化为桥行（桥即状态）；
- WHITE ∩ FREEZE = **双向拒绝**（spec D4）：两边都不执行、面板 bad 红高亮；
- hook 侧任何异常 **fail-open 放行**（spec §6.3），绝不影响名单外进程与既有 killLocked 链；
- 复用管道：事件 = `TS|pid|pkg|rule|act|reason` 6 字段 append 到 `data/guard/YYYY-MM-DD.log`；热加载 = service.sh 30s + hook 5s mtime；
- 测试先行：每个代码改动先写失败测试；全量门槛 = 新测试 + 既有 all.sh + vitest 32 全绿；
- 开发在分支 `feat/freeze`，不动 guard 日用现场；目标版本 v0.5.0；
- 路径常量：`M=/data/adb/modules/COSMemory`、`LIST=/sdcard/Android/COSMemory/名单列表.conf`、桥 `/data/system/cosmem/guard.conf`。

    done
  done
  FREEZE_CONFLICT="${CONFLICT# }"

- [ ] **Step 3: 实现 freeze_active 与 freeze_reap**

`engine/memory.sh` 新增（放在 `plan_keepalive` 调用所在主循环之前）：

```sh
freeze_active() { # $1=桥路径; 输出 1/0
  [ -f "$1" ] || { echo 0; return; }
  grep -q '^FREEZE_ENABLED=1' "$1" 2>/dev/null || { echo 0; return; }
  grep -q '^FREEZE ' "$1" 2>/dev/null && echo 1 || echo 0
}
freeze_reap() { # $1=桥路径; 其余=包名; 成功杀输出 act 行到 stdout
  local br="$1"; shift
  [ "$(freeze_active "$br")" = 1 ] || return 0
  local pkgs p pid
  pkgs=$(grep '^FREEZE ' "$br" | awk '{print $2}')
  for p in "$@"; do
    echo "$pkgs" | grep -qx "$p" || continue
    for pid in $(pgrep -f "^$p( |:|$)" 2>/dev/null); do
      am kill "$p" >/dev/null 2>&1
      echo "$(date +%s)|$pid|$p||FREEZE|engine reap"
      return 0
    done
  done
  return 0
}
```

主循环内（`plan_reclaim` 行之后）追加巡检行：

```sh
FRZ=$(freeze_reap "$BRIDGE_PATH" $FREEZE_LIST 2>/dev/null)
[ -n "$FRZ" ] && echo "$FRZ" >> "$GUARD_LOG"
```

其中 `BRIDGE_PATH=${BRIDGE_PATH:-/data/system/cosmem/guard.conf}`、`GUARD_LOG=$WORKDIR/guard/$(date +%F).log`（对齐既有事件文件路径；若主循环已有同名变量定义则复用）。
